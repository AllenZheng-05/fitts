# Baseline comparison: plan (pre-registered)

Written and committed before any run of the comparison, with the strata labels in
`demo/chat/PLANTED.md` in the same commit. Results go in `docs/bench/RESULTS.md`, one row per
run, bad numbers included; nothing here changes after the first run except to add a note
saying what changed and why.

## Questions

1. Is Fitts more than axe? What does each part of Fitts find that a rules engine can't?
2. What does each Meta model add: Muse Spark (Economy), Muse Wonder (Quality), Muse Spark Open
   (Open), and the Wonder judge (ablation)?

## Datasets

| Dataset | Answer key | Use |
|---|---|---|
| `demo/chat` | `demo/chat/PLANTED.md`, 33 planted issues, each labeled S1 or S2 | recall, precision |
| The held-out app | sealed until Allen reveals it; SHA-256 committed in the app's repo and README | blind run, then recall per stratum and false alarms on its 3 traps (T) |
| Basil & Ember web (`demo/basil-ember`) | none (generated by Muse Code, untouched) | qualitative: what each arm finds |

**Strata.**
- **S1, structure-detectable:** findable from the DOM, the accessibility tree or measurements
  (contrast, sizes, missing names, request counts, status codes).
- **S2, judgment or visual:** needs a person's judgment, the screen, timing, or the app's intent
  (wording, flow, feedback, consistency, what a page is for).

## Arms

All arms see the same routes and the same two viewports: desktop 1280×800 and phone 390×844.
For `demo/chat`: `/`, `/compose`, `/compose/recipient`, `/compose/confirm`, `/search`,
`/contacts`, `/contacts/grandma`, `/settings`.

| Arm | What runs | Models |
|---|---|---|
| a. axe | axe-core, every rule, on each route at both viewports; one finding per violated rule and route | none |
| b. Lighthouse accessibility | only if it can be added without a new install; otherwise skipped, and the results say so | none |
| c. Fitts, probes only | the offline crawl (`BENCH_OFFLINE=1`): Fitts's deterministic probes, no reviewers, no judge | none |
| d. Fitts Economy | `bench:chat`, Economy profile | Muse Spark 1.3 |
| e. Fitts Quality | `bench:chat`, Quality profile | Spark, Wonder, the Wonder judge |
| f. Fitts Open | `bench:chat`, Open profile: Muse Spark Open on Baseten for every reviewer, the merging of findings and the theme check | Spark Open, Spark |
| g. Fitts Economy without the judge | arm d with the Wonder judge turned off (ablation) | Muse Spark 1.3 |

The answer keys are hidden from Fitts in every arm (`FITTS_HIDE_FILES`). Paid arms run twice
where the budget allows, to show the variance; each run is its own row.

## Metrics

- **Recall:** planted issues matched, overall and per stratum (S1, S2), with the same matcher
  for every arm (`apps/desktop/tests/bench/planted.ts`: route or element, and the issue's words in
  the finding's title and text).
- **Precision:** shown findings that match a planted issue, strict (all severities) and at
  severity ≥ 2.
- **False alarms** on the held-out app's traps (T).
- **Cost** (the ledger, in USD) and **wall time** per run.

A finding from axe is scored like a Fitts finding: its rule's help text is the title, the
violation's description the text, its node's `data-ref` the element.

## Budget

$25 in total for all paid runs, stopping early if a run misbehaves (a crash, a stuck run, or
spend far beyond the others). A run that's stopped is still a row, marked as stopped.

## Output

- `docs/bench/RESULTS.md`: each run's id, date, arm, dataset, recall (overall, S1, S2),
  precision (strict, ≥ 2), false alarms, cost and wall time. Never a mix of runs in one row.
- One summary line in `docs/PROGRESS.md`, for the README, the site and the video, e.g. "axe
  alone: X/33 (S1 a, S2 b) · Fitts Economy: Y/33 (S1 c, S2 d)".
